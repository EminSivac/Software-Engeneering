# Feedback System and Model Evaluation Documentation

## 1. Overview

The application allows users to evaluate waste classification predictions generated by multiple AI models.

Its main purpose is to continuously collect verified feedback data and compute model performance metrics over time.

Instead of only showing the current prediction, the system also displays two historical performance indicators per model and waste category:

- **Prediction Reliability (Precision)**
- **Category Detection Rate (Recall)**

These metrics are computed from previously collected user feedback stored in the database.

The system does not retrain the AI models. User feedback is only used to evaluate and compare model performance.

---

# 2. System Workflow

After an image is analyzed, each AI model returns:

- predicted waste category (`müllart`)
- recommended waste bin
- confidence level (`sicherheit`)

These results are stored in the `results` table before user feedback is collected.

Each model result card allows the user to submit feedback:

- Correct
- Wrong
- Don't know

---

# 2.1 Correct

If the user selects **Correct**, the prediction is considered verified.

Stored data:

- predicted_material
- actual_material = predicted_material
- correct = 1

**Example:**

| predicted_material | actual_material | correct |
|-------------------|----------------|---------|
| Plastic/Verpackungen | Plastic/Verpackungen | 1 |

---

# 2.2 Wrong

If the user selects **Wrong**, the system requests the correct category via a dropdown selection.

Supported categories:

- Papier
- Plastic/Verpackungen
- Bio/Organisch
- Restmüll

Stored data:

- predicted_material
- actual_material = user-selected category
- correct = 0

**Example:**

| predicted_material | actual_material | correct |
|-------------------|----------------|---------|
| Plastic/Verpackungen | Papier | 0 |

This creates verified labeled data that can be used for evaluating model performance.

---

# 2.3 Don't Know

If the user selects **Don't know**:

- feedback is stored in the feedback log only
- no correctness value is assigned
- the result entry is not updated

These entries are excluded from all evaluation metrics.

---

# 3. Frontend Behavior

Each model card displays:

- predicted waste category
- recommended waste bin
- confidence level
- Prediction Reliability
- Category Detection Rate
- feedback buttons

## Feedback Actions

- **Correct** → immediately sent to backend
- **Wrong** → opens correction dropdown before submission
- **Don't know** → sent immediately without updating ground truth

All feedback is sent via:
POST/feedback 


## Payload includes:

- resultId
- model name
- predicted material
- actual material (if provided via correction)
- waste bin
- confidence level
- feedback type

---

# 4. Backend Implementation

## Endpoint
POST/feedback 


Each request performs two operations:

---

## 4.1 Feedback Logging

All feedback entries are stored in the `feedback` table, regardless of correctness.

This preserves a complete interaction log.

---

## 4.2 Updating Prediction Results

Only **Correct** and **Wrong** feedback update the `results` table.

### Correct:

- correct = 1
- actual_material = predicted_material

### Wrong:

- correct = 0
- actual_material = user-selected category

### Don't Know:

- no changes to results table

---

# 5. Database Design

## 5.1 Results Table

Stores AI model predictions and validated labels.

| Column | Description |
|---|---|
| id | Prediction ID |
| model | AI model name |
| predicted_material | Material predicted by the AI model |
| actual_material | Verified label from user feedback |
| correct | 1 = correct, 0 = incorrect |
| latency | Response time |
| created_at | Timestamp |

Initially only `predicted_material` exists.

After feedback:

- `actual_material` is updated
- `correct` receives a value

---

## 5.2 Feedback Table

Stores raw user interaction logs.

| Column | Description |
|---|---|
| id | Feedback ID |
| model | AI model |
| material | Material predicted by the AI model |
| bin | Predicted waste bin |
| safety | Model confidence |
| feedback | User response (`yes/no/dont_know`) |
| created_at | Timestamp |

This table is independent from the evaluation logic.

# 6. Model Evaluation Metrics

The system computes two separate metrics per model and waste category.

---

# 6.1 Prediction Reliability (Precision)

**Meaning:**

> When the model predicts a category, how often is that prediction correct?

**Formula:**
Prediction Reliability = Correct predictions for category  / All predictions of that category


Based on:

- predicted_material
- correct

Function:
getPredictionReliability(model, material)


---

# 6.2 Category Detection Rate (Recall)

**Meaning:**

> When an item actually belongs to a category, how often does the model correctly identify it?

**Formula:**
Category Detection Rate = Correct predictions for category / All real instances of that category


Based on:

- actual_material
- predicted_material

Function:
getCategoryDetectionRate(model, material)


---

# 6.3 Example

| Actual Category | Predicted Category | Correct |
|---|---|---|
| Plastic/Verpackungen | Plastic/Verpackungen | ✓ |
| Plastic/Verpackungen | Plastic/Verpackungen | ✓ |
| Plastic/Verpackungen | Restmüll | ✗ |
| Plastic/Verpackungen | Plastic/Verpackungen | ✓ |

Results:

- Prediction Reliability = 100%
- Category Detection Rate = 75%

Explanation:

- The model predicted Plastic 3 times and all 3 predictions were correct.
- There were 4 actual Plastic items, but only 3 were detected.

# 10. Benefits

The system provides:

- continuous evaluation using user feedback
- real-world validation of AI predictions
- separation of precision and recall metrics
- per-model and per-category evaluation
- scalable dataset generation without manual labeling
- foundation for advanced metrics such as confusion matrix and F1-score

# Summary

The application evolves from a simple classification tool into an evaluation platform for comparing AI models.

As more verified feedback is collected, Prediction Reliability and Category Detection Rate become increasingly meaningful indicators of real-world model performance.
