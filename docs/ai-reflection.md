# AI Reflection

## How AI Was Used During Development

AI was used as a supporting tool during the development of this project, not only inside the final application idea but also during planning, coding, and documentation.

The team used AI especially for:

- writing and improving documentation
- supporting implementation work
- reviewing structure and logic during development
- helping translate rough ideas into concrete next steps

## Documentation Support

AI was used to help document the project in a clearer and more structured way.

This included support for:

- rewriting technical explanations in clearer English
- structuring README and project documentation
- summarizing implementation details
- checking whether documentation still matched the real codebase

In this role, AI helped reduce time spent on rewriting and organizing written material.

## Coding Support

AI was also used during implementation.

It supported the project not just by suggesting code, but as a critical partner that helped with both planning and execution.

This included:

- discussing implementation approaches
- identifying mismatches between the intended design and the existing code
- suggesting concrete code changes
- helping turn ideas into working implementation steps
- supporting cleanup and restructuring tasks

## Role as a Critical Partner

AI was most useful when treated as a critical partner instead of an automatic code generator.

That means it contributed by:

- questioning unclear assumptions
- helping break down tasks into manageable steps
- supporting decision-making during planning
- assisting with implementation once the direction was clear

This made AI useful in both the conceptual phase and the practical development phase.

## Verification and Understanding of AI-Generated Code

AI-generated code was not accepted blindly.

To verify suggestions, we used several practical checks:

- thinking through parts of the code manually before using them
- copying smaller code ideas into the project for short tests
- running and debugging code step by step to understand what it actually did
- checking whether the behavior matched the intended logic

This process was important for understanding the code instead of only trusting the generated result.

In some cases, code produced by AI was adopted almost completely. However, those parts were still based on prior human reasoning.

The implementation direction was first thought through by a human, and only then supported by AI. The code was therefore not simply taken over from AI without review, but used after validation and understanding.

## Reflection

The main benefit was speed and support during routine and structural work, especially for documentation and implementation guidance.

At the same time, human review remained necessary because:

- generated suggestions still needed validation
- the final code had to match the real project state
- documentation had to reflect the actual implementation, not only intended behavior

Overall, AI supported the team as a practical development assistant that helped with documentation, planning, and coding.
